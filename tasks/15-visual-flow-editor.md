# Task 15: Visual flow editor

## Goal
Tier 3: a canvas where the flow graph can be seen and then edited, with validation owned by the server. Read only first, editing second, and the linear editors keep working throughout.

## Read first
UI review at `docs/ui-review-2026-10-29.md` section 3. ARCHITECTURE.md (flow schema). Depends on task 14.

## Do
- Add `@xyflow/react` (MIT, maintained React Flow) to the web app. Do not write a canvas by hand.
- Route `/libraries/:id/flow`, reachable from the rules page tier selector.
- Phase 1, read only: render the graph generated by easy mode or step stack, with pan, zoom, minimap, and a read only inspector that shows each step's parameters. This teaches the model before anyone can break it.
- Phase 2, editing:
  - Node palette on the left built from `GET /api/v1/flows/step-types`, so the palette is server driven.
  - Inspector on the right for the selected step's parameters, with types rendered from the parameter schema.
  - Connect and delete edges, add and delete steps, automatic layout on first open.
  - Every change calls `POST /api/v1/flows/validate` and renders returned errors on the node itself. The client never decides whether a graph is valid.
  - Save writes the whole graph with `source=advanced`.
- Keyboard and accessibility: every action available from a menu as well as by drag, since drag and drop alone is not usable for everyone.
- Guard rails: warn before leaving with unsaved changes, and disable Save while the graph is invalid with the reason shown.

## Out of scope
Branching beyond conditions, loops, custom code steps, collaborative editing, undo history beyond a single step undo.

## Acceptance
- [ ] The flow for an easy mode library renders read only with the correct number of nodes and edges, on the same graph object the API returns. (`FlowCanvas.test.tsx`)
- [ ] Adding a step, connecting it, and saving persists it, and `GET /api/v1/libraries/{id}/flow` returns `source=advanced`. (`TestFlowCanvasSave`, plus a Go round trip)
- [ ] An invalid edit (an orphan node or a missing parameter) shows the server's field error on the node and blocks Save. (`FlowCanvas.test.tsx`)
- [ ] Switching a Steps library to Advanced keeps every step; switching back to Steps warns that manual graph structure will be lost. (`RulesPage.test.tsx`)
- [ ] The palette is built from the API response, verified by adding a step type in a test fixture and seeing it appear. (`FlowCanvas.test.tsx`)
- [ ] No regression: the easy mode and step stack editors still pass their tests and still produce identical compiled plans.
